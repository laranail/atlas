# Architecture

How the package is layered, what is enforced rather than agreed, and why the
decisions that look odd are the way they are.

## The layering

```
src/Core/          framework-free. No Illuminate, no chrono, no laranail/*
  Contracts/       PlaceRepository, IpCountryResolver, DistanceCalculator
  Country/         CountryRecord, CountryQuery
  Geo/             Coordinates, BoundingBox, Distance, Haversine, Vincenty
  Network/         IpAddress, IpRange, IpRangeTable
  Currency/ Language/ Region/ Exception/ Support/

src/Adapters/      the extension seam
  Generated/       the shipped dataset — default, zero dependencies
  Rinvex/          rinvex/countries, optional

src/Services/      AtlasService (the query API), AtlasManager (driver registry)
src/Bridges/       Chrono — class_exists-guarded, optional
src/Http/  Rules/  Console/  Facades/  Providers/
```

## `Core/` is framework-free, and it is enforced

deptrac holds the boundary, and `composer deptrac` is part of `composer lint`,
so a `use Illuminate\…` inside `Core/` fails CI rather than being noticed in
review.

Two things make that guard real rather than decorative:

- **A guard script wraps deptrac**, because **deptrac exits 0 on a file it
  cannot parse**. A syntax error inside `Core/` would otherwise read as a clean
  boundary. `tools/deptrac-guard.php` fails on parse errors as well as
  violations.
- **The unit tests do not boot a container.** `tests/Unit` deliberately avoids
  the Testbench base case, so a `Core/` class that starts needing the container
  fails at runtime too. Static and dynamic proof of the same property.

The point is not purity. It is that the country catalogue, the distance maths
and the IP range table are testable without a Laravel application, reusable
outside one, and cheap to reason about — and that the *reason* the old toolkit
module was hard to extract was that none of that was true of it.

## `PlaceRepository` is the seam

Four methods: `all()`, `find()`, `isAvailable()`, `version()`.

Deliberately narrow. Everything derivable from the full list — groupings, select
options, region indexes, name searches — is computed **above** this interface
rather than demanded of every adapter. A source implements four methods; it does
not reimplement the query layer.

That narrowness is the fix for the specific failure this package replaces. The
toolkit module returned arrays shaped by whatever `rinvex/countries` exposed, so
the data package was load-bearing in *every consumer*, not just in the loader —
which is why it could not be swapped and why removing it meant touching call
sites everywhere.

## The registry is an enum plus a closure, never a `Manager`

`AtlasManager` resolves a provider by matching on the `Provider` enum.
`extend()` takes a **closure, not a class name**.

`Illuminate\Support\Manager` interpolates a driver name into a method call, and
that name arrives from a config file an operator edits — in a multi-tenant
install, from a database row. A config string must never be able to become a
method name or a class name. The enum is the allow-list: a name that is not a
case never resolves at all.

## Generated data, with a version stamp and a check

`resources/data/countries.php` is generated by `tools/build-dataset.php` and
stamped in `dataset-version.txt`. The four enums — `Country`, `Currency`,
`Language`, `Provider` — are generated from that same file by
`tools/generate-enums.php`, and `composer sync-check` re-runs the generator with
`--check` so a hand-edited enum or a regenerated dataset without regenerated
enums fails CI.

Generated files are excluded from Pint and Rector. A reformatter would put the
committed artefact and the generator permanently at odds, and the resulting diff
would be reformatting noise on every regeneration.

## Why languages are ISO 639-3

The dataset carries `eng` and `swa`, not `en` and `sw`, and the `Language` enum
is generated from it. Two-letter 639-1 codes cover a few hundred languages;
639-3 covers every one with a code, which is what a country's language list
actually needs. Accepting both would mean shipping a mapping table and deciding
which form to store — so the package takes one form and says which, in the
validation message as well as here.

## Why `Distance` is an object

`distanceBetween($a, $b, 'mi')` returns a float whose unit was decided by a
string argument several lines earlier, and every consumer re-derives what that
float means. `Distance` carries its own unit and converts, so the question
"kilometres or miles?" is answered where it is asked rather than where the value
was produced.

## Why Vincenty is not the default

It is a thousand times more accurate and it does not always terminate. The
inverse formula oscillates rather than converging for near-antipodal points, and
a geo helper that hangs — or silently returns its last iterate — on two specific
points is worse than one that is accurate to 0.5% everywhere.

So Haversine is the default, Vincenty is opt-in, and when Vincenty fails to
converge the answer falls back to the spherical one with `converged()` reporting
it. The failure is visible rather than absorbed.

## Why the chrono bridge is a `suggest`

Taking `laranail/chrono` as a `require` would raise this package's floor to PHP
`^8.5` — chrono is the only package in the family that high — and cut atlas off
from every `^8.4` consumer for a feature most of them will not use.

So the bridge is `class_exists`-guarded — and because chrono's floor means it
cannot be a dev dependency without breaking the 8.4 leg of the matrix, **the
whole default suite already runs without it**. The absent-path is the one that
is exercised on every push.

That leaves the opposite risk: the present-path never running, with the bridge's
own tests skipping silently forever. A dedicated `with-chrono` job on 8.5
installs it and asserts the class is actually there before running the suite, so
a skip cannot masquerade as a pass.

`rinvex/countries` is the mirror image — it *is* a dev dependency, so a
`without-rinvex` job removes it and proves the shipped dataset stands alone.

## The IP table is built, not shipped

Registry delegation data changes daily and is large. Shipping a snapshot would
mean every install of a package most people want for its country catalogue
carried a table that was stale the day it was tagged.

So `tools/build-ip-table.php` fetches it and `countryForIp()` answers `null`
until you do. The distinction that matters is between *no table* and *no
allocation*, and both `doctor` and the API's `reason` field make it, because a
silent null makes a deployment problem look like the shape of the internet.

## Where the boundary with `ip-intel` is

Registry data gives **country, and the fact of an allocation**. It does not give
city, ISP name, or VPN/proxy status, and those cannot be derived from it. This
package therefore answers country and stops.

[`laranail/ip-intel`](https://opensource.simtabi.com/documentation/laranail/ip-intel/)
is where the rest lives, and it uses this as its free offline tier — asking a
metered API for a country when a local table has the answer is paying for
something you already have.
