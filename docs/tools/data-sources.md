# Data sources

The catalogue comes from a `PlaceRepository`. Three are named, one ships, and
registering your own takes a closure.

## The seam

```php
interface PlaceRepository
{
    public function all(): array;              // array<string, CountryRecord>, keyed by alpha-2
    public function find(string $code): ?CountryRecord;
    public function isAvailable(): bool;
    public function version(): ?string;
}
```

Four methods, deliberately. Everything derivable from the full list —
groupings, select options, region indexes, name searches — is computed *above*
this interface rather than demanded of every adapter. A source implements four
methods; it does not reimplement the query layer.

That narrowness is the fix for the specific failure this package replaces. The
toolkit module returned arrays shaped by whatever `rinvex/countries` exposed, so
the data package was load-bearing in **every consumer**, not just in the
loader — which is why it could not be swapped.

## The three named sources

```php
'provider' => env('ATLAS_PROVIDER', 'generated'),
```

| Value | Source | Needs |
|---|---|---|
| `generated` | The shipped dataset — 250 countries, a flat PHP array | nothing |
| `rinvex` | `rinvex/countries` | `composer require rinvex/countries` |
| `remote` | A hosted catalogue | **reserved; not implemented** |

`generated` is the default and is why the package has no data dependency. The
array is held by OPcache as compiled opcodes, so a lookup costs an array read.

## Registering your own

```php
// A service provider's boot()
use Simtabi\Laranail\Atlas\Core\Contracts\PlaceRepository;
use Simtabi\Laranail\Atlas\Services\AtlasManager;

app(AtlasManager::class)->extend('acme', fn (): PlaceRepository => new AcmeRepository($db));
```

Then `ATLAS_PROVIDER=acme`.

Through the manager and not the `Atlas` facade, which proxies `AtlasService` —
the query API — and nothing else. Registering a source is a one-line act in a
provider; asking which countries use the euro happens everywhere, and only the
second earns a facade.

### Why a closure and not a class name

`extend()` takes a **closure**. The config value selects among names that have
been registered in application code; it can never itself become a class name.

This package does not use `Illuminate\Support\Manager` for the same reason. A
`Manager` interpolates the driver name into a method call, and that name arrives
from a config file an operator edits — in a multi-tenant install, from a
database row. The `Provider` enum is the allow-list for the built-in three, and
`extend()` is the only way to add a fourth.

## Availability and version

```php
Atlas::describe();
// ['provider' => '…\GeneratedPlaceRepository', 'version' => '2025-07-14 rinvex/countries v9.1.0',
//  'available' => true, 'countries' => 250,
//  'distance' => 'haversine', 'ip_ready' => false]
```

`isAvailable()` is answered without loading the dataset where possible — it is
what `doctor` calls, and what the factory checks before handing back an adapter
whose data package is missing. A configured provider whose package is not
installed otherwise returns an empty catalogue, and an empty catalogue makes
every country look nonexistent rather than raising anything.

`version()` returns **null** when a source cannot date itself, and `doctor`
reports that as *unknown* rather than *current*. A source that cannot be dated
cannot be checked for staleness, and calling it fine would be a guess dressed as
a result.

A stamp that is present but carries no leading `YYYY-MM-DD` gets the same
treatment — undatable, and warned about. `doctor` parses exactly that one
leading token and nothing looser: the check it replaces threw the whole stamp at
`strtotime()`, which returns false for a source string, so it reported every
dataset the package has ever shipped as current. Your own source is free to stamp
whatever it likes; prefixing a date is what buys it an age check.

## The shipped dataset

`resources/data/countries.php` + `resources/data/dataset-version.txt`,
generated by `tools/build-dataset.php`.

The three generated enums come from the same file, and `composer sync-check`
re-runs the generator with `--check` so a regenerated dataset with
un-regenerated enums fails CI. See [enums](enums.md#generated-and-checked).
